# Apple Metal equity path: benchmarks and tests (2026-11-24)

**Scope.** A GPU path for the Monte Carlo equity calculation, for local benchmarking and research on Apple Silicon only (tested on an M4, 16 GB). It lives on branch `research/metal`, is compiled in only with `-DUSE_METAL` on macOS, and can be switched off at runtime with `POKER_NO_METAL=1`. The shipped bot is a linux/amd64 Docker image and stays pure C++.

**Why.** Profiling showed the offline bench spends about 93% of its time in the C++ Monte Carlo (vs September at 100 bb; 83% vs reference at 15 bb). The bluff-frequency path was the most expensive call, about 33 ms, because it runs about 43 small simulations.

**Design.**
- A batch API: one GPU dispatch covers many equity jobs, so the bluff path's ~43 simulations become one call.
- A bitmask 7-card evaluator in Metal Shading Language, compiled at runtime (no Xcode Metal toolchain needed).
- A PCG32 generator seeded per thread; a nonzero seed repeats for the same batch contents.
- The opponent is dealt from the credited range's allowed combos; the board is completed from the remaining deck.

## Speed, one process

| Case | CPU | GPU |
|---|---|---|
| One decision, 2,000 trials | 4.03 ms | 0.45 ms |
| One decision, 5,000 trials | 10.15 ms | 0.58 ms |
| Bluff path, 43 x 300 batch | 24.74 ms | 0.41 ms |
| 1,000,000 trials | 2,083 ms | 3.4 ms |

## Speed under load: nine bench processes sharing the GPU

| Run | GPU | CPU | Speed-up |
|---|---|---|---|
| vs reference, 15 bb, 9 x 1,000 hands | 1.67 s | 14.20 s | 8.5x |
| vs september, 100 bb, 9 x 400 hands | 15.66 s | 29.35 s | 1.9x (the September opponent still runs on the CPU) |

## Correctness

| Check | Result |
|---|---|
| Targeted evaluator deals (royal and straight flushes, wheel, steel wheel, quads, full houses, flush vs flush and vs straight, counterfeits, kickers, boards that play), each also seat-swapped | 70 deals, 0 failures |
| Random deals vs the CPU evaluator | 2,000,000 deals, 0 mismatches |
| Equity on 60 random spots (GPU 400k vs CPU 200k trials) | max z = 2.68 (limit 4) |
| AA vs KK equity | GPU 0.8269, CPU 0.8237 (expected about 0.826) |
| Seeded repeat | identical; a different seed differs |
| Runtime switch-off | `POKER_NO_METAL=1` reports the GPU unavailable |
| Mutation check | swapping straight and flush in the GPU evaluator makes the targeted test fail |

**Bench-level sanity (paired, 4,000 hands vs reference at 15 bb):** CPU +52.7 [+48.9, +56.5], GPU +53.0 [+49.2, +56.8], difference -0.3 [-2.0, +1.4]. The GPU path plays like the CPU path.

**Caveats.**
- GPU and CPU use different random generators, so paired comparisons should keep both builds on the same engine type.
- A seeded GPU result repeats only when the batch contents match; identical spots produce identical batches, so paired bench comparisons still work.
- Each call allocates fresh buffers; no buffer reuse yet.
